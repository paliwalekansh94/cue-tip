# Cue Tip v0.3 — Cloudflare D1 integration staging

**Status:** Database schema has been created in Cloudflare D1. A read-only Worker health-check entrypoint and D1 binding are configured in `wrangler.jsonc`. Production deployment and live connectivity still require verification. The customer/staff frontend remains a browser-local demo.

## Architecture
- Frontend: React + Vite on Cloudflare Workers Static Assets
- Proposed backend: `worker/index.ts` with D1 binding `DB`
- Migration: `migrations/0001_initial.sql`
- Billing core: `worker/billing.ts`
- Snooker ₹6/min and Pool ₹5/min; both +₹1/min per player beyond two; PS5 ₹5/min without surcharge.
- Billing uses historical rate segments and excludes paused intervals. The staged server billing policy rounds the **total play charge up to the next rupee**, rather than rounding each minute. Confirm this policy before production use.
- Match wins drive leaderboard ranking; win percentage breaks ties.
- Snacks use historical price snapshots so menu changes do not rewrite past bills.

## Owner setup required (Cloudflare dashboard)
1. Open **Storage & databases → D1 → Create database**.
2. Name it `cue-tip-db` and create it.
3. Copy the database ID from its details (a UUID). This is an identifier, not an API token.
4. Send the database ID to the developer, or provide it in the Cloudflare Worker D1 binding settings.

**Do not paste API tokens, passwords or secrets in chat.**

## Security and release gates
The new API is intentionally NOT connected to the live deployment. Its temporary `STAFF_API_KEY` header is only an integration gate, **not suitable as production staff authentication**, particularly from a browser. Before enabling production writes:
- Implement login with individual identities and server-side roles (owner, staff, customer), audit attribution, session cookies, CSRF protection, rate limits and appropriate authorization.
- Test transactional correctness and concurrent starts, pause/resume, player changes, refunds, rounding, and receipts.
- Confirm whether snacks are taxed and whether menu prices are inclusive of GST.
- Move all live state and pricing to the API; remove browser-local demo billing.
- Back up D1 and verify migrations in a staging database before production.

The current `wrangler.jsonc` intentionally enables only the read-only health check (`worker/entry.ts`); the full billing API (`worker/index.ts`) is NOT activated. This documentation update also triggers a fresh GitHub-connected Cloudflare build after reconnecting the Git integration.
